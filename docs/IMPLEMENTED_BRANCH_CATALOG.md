# PolyEc — mục lục bằng chứng triển khai theo nhánh

Cập nhật 2026-10-23. Danh mục này lập từ **200 report Markdown** đang có trong `docs/reports/` (không tính README của thư mục). Nó nối nhánh implementation với plan/report để review; không thay CURRENT_TASK, không kết luận “xong” theo tên file và không thay report gốc.

## Cách xác định nhánh đã thật sự hoàn tất

Mỗi report có thể ghi kết quả pass, fail, một phần, thử nghiệm bị loại, chỉ build hoặc phần tích hợp còn chờ. Đọc phần kết luận/giới hạn trong report trước khi gán trạng thái. Plan là đặc tả ý định trước code, không tự chứng minh đã triển khai. Report chỉ là bằng chứng cho revision/run được ghi bên trong, không chứng nhận source HEAD mới hơn.

Báo cáo M3/M4 là hai nguồn lớn đang giữ các nền tảng cũ: M3 gồm sandbox native, shared C++/Python, hệ thống kinh tế/xã hội và đánh giá pilot; M4 giữ vertical slice sáu vùng, Hắc Sơn, xưởng, logistics, save và native UI. Không có report độc lập cho từng M0, M1, M2; không suy ra ba mốc đó hoàn chỉnh chỉ từ report M3/M4. Đích mỗi mốc ở [IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md), cây kỹ thuật ở [TECHNICAL_PROBLEMS](TECHNICAL_PROBLEMS.md), phân rã milestone ở [MILESTONE_BLUEPRINTS](MILESTONE_BLUEPRINTS.md).

| Core refactor R4 | 20 | Codec/schema/view từng nhóm và tích hợp R1–R4 | Tách kết quả mỗi lát với kết quả tích hợp. |
| M5 | 177 | Producer, household, route, market, military, knowledge, RL/performance | Có feature, audit, benchmark, thử nghiệm và tích hợp; không phải mọi report chứng minh một feature hoàn tất. |

## Quy tắc biến report thành blueprint có thể dùng để viết lại code

Report là bản ghi chạy; để tái tạo implementation, từng nhánh cần plan/contract có: mục tiêu; input và nguồn; giới hạn/đơn vị; ownership; thuật toán; output; reject/edge; save/migration; API owner/caller; oracle; test target ngay và lớp tích hợp. Nếu report có kết quả nhưng không tìm thấy plan/contract, đó là khoảng trống tài liệu cần xử lý trước khi dùng làm hướng dẫn viết lại.

Khi nhóm code hoàn tất, cập nhật CURRENT_TASK, plan/blueprint bị ảnh hưởng, report và HISTORY theo [DEVELOPMENT_WORKFLOW §5.1](DEVELOPMENT_WORKFLOW.md#51-cap-nhat-docs-khi-mot-phan-code-hoan-tat). Không đổi mã nhánh hoặc xóa report cũ để gọn. Trạng thái đang làm lấy từ CURRENT_TASK; report cũ chỉ giữ bằng chứng revision/run của nó.
