## Implemented behavior

- **Settlement factor**: `kAttendanceTicksPerWorkUnit = 16` in `core/include/polyec/schedule.hpp`. T=16 is a **Codex-delegated working assumption, not direct user instruction and not balance approval**. With `kSubdayUnitsPerDay = 64`, maximum full attendance yields 4 units/day.
- **Settlement point**: `Realm::day_settlement()` runs as the final phase of `RealmDayPipeline::run`, after `day_end()`, so it runs once per completed day boundary.
- **Eligibility**: for each valid actor with cumulative `work_present_ticks`, `eligible = ticks / 16` (integer floor). The stored `settled_work_units[actor]` is raised only when `eligible` is greater than the prior value, so cumulative attendance is never double counted and remainder ticks carry implicitly.
- **Watermark**: `settled_day = cursor / 64`.
- **Bookkeeping only**: settlement does not change attendance, sessions, people, provinces, cash, facts, RNG, production, payroll or any economic quantity. Units are not effort, output, pay, wage or a claim on resources.
- **Sparse deterministic state**: `ScheduleBook` adds `int64_t settled_day` and `std::unordered_map<uint64_t,int64_t> settled_work_units`. Only positive entries are stored; zero entries are normalized away on load.
- **Save**: `POLYEC_REALM_9` / `SCHEDULE_3`. The schedule header adds `settled_day` and a settled count; settlement records are serialized by ascending actor ID for stable bytes and fingerprints.
- **Load validation**: settled count ≤ `people_.size()`; actor IDs unique and in range; `settled_day ∈ [0, floor(cursor/64)]`; units ≤ `floor(cursor/16)` and ≤ `floor(attendance/16)`; non-empty settlement requires `settled_day > 0`; settlement and attendance must be empty when `timeline_contract == false`.
- **Migration**: `POLYEC_REALM_8` / `SCHEDULE_2` preserves typed sessions and attendance with empty settlement (`settled_day = 0`) before re-serializing as v9. `POLYEC_REALM_7` / `SCHEDULE_1` defaults sessions to `Generic` / `region = -1` and starts attendance and settlement empty before re-serializing as v9.
- **Python binding**: read-only `settled_day` and `settled_work_units(actor)`; no writer exists, so mutation stays behind the Realm command and day path.
- **Unchanged**: action/`Intent`/mask/legality, observation, `realm_obs`/`realm_state`, `model_contract`, bundle/training, `day_production`/`day_payroll`, and attendance accounting itself.

## Test coverage added

- Boundary conversion: 15 ticks → 0 units, 16 → 1, 31 → 1, 32 → 2.
- Multi-day cumulative settlement with remainder carried; one-shot and split advances produce the same fingerprint.
- Idle days do not re-credit previously settled units.
- Legacy timeline without typed Work carries no settlement and no backfill; later Work settles only from its actual attendance.
- v9 round-trip preserves typed sessions, attendance and settlement; v8 migration preserves sessions/attendance with empty settlement; v7 migration defaults Generic/`-1` with empty attendance and settlement.
- Corrupt settlement rejected: count limit, negative units, settled day beyond cursor, invalid/duplicate actors, zero-unit entries, units over cursor, units beyond attendance, settlement with `timeline_contract == false`, and settlement on day zero.
- Zero settled units normalized away; mid-day save/restore continues without re-crediting.
- Python binding replay covers mid-day empty settlement, boundary settlement, restore, and generic-only zero units.
