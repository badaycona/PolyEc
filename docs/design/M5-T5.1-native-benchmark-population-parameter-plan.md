# M5 T5.1 — native benchmark population parameter

## Goal

Expose the existing `RealmRuntime::load_models(..., population)` input in the native benchmark CLI, so the same realm-v6 pilot ONNX models and deterministic workload can measure 10k and 100k worlds. The local v6 manifests currently report `full_R1_pass: false`; an inference run is not a learned-policy quality pass. This is benchmark harness work only; it does not change game rules or count a partial scale run as profile B acceptance.

## Files and behavior

- `native/realm_benchmark.cpp`: accept an optional `population` argument after seed; preserve existing invocation/default at 10,000. Validate 128–1,000,000 before loading models. Include requested population and profile label in output JSON.
- `native/realm_runtime.cpp`/header: no code change; `load_models` already accepts the population.
- Build the existing `polyec_realm_benchmark` target from `build/m5-runtime`. Run existing model artifacts only; no training or model rewrite.
- Tests: preserve old CLI invocation; run 31 days at 10k and 100k with the same seed so the existing route shock at day 30 actually occurs. Keep output labeled `B-population-scale-only` because complex actor count remains 128 and render/save, multi-seed, 20-year stability, 512–2048 complex actors, and full-cycle costs are outside this slice. Record whether the route shock ran (`days > 30`).

## Acceptance

- Release target builds; legacy/default and explicit population paths produce valid JSON with invariant and money-conservation fields.
- Record seed, model contract/fingerprint, days, wall time, p50/p95/max, population and complex-actor count. Do not compare against profile A as a like-for-like speedup unless hardware/build/model/workload match.
- Self-review the CLI bounds, output labeling and unchanged runtime semantics. M5.5 stays open.
