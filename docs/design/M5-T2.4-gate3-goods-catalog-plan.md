Date: 2026-10-20. Status: reviewed bounded plan and accepted implementation. Scope was checked against `CURRENT_TASK`, `IMPLEMENTATION_PLAN` §§4, 15.2–15.3, Gate 1/2, and the delegated T2.4 contract. ## Objective

Replace seven positional pilot goods with stable canonical product IDs under the 16 target groups, while migrating every Realm and Campaign holding without loss. Model the explicitly documented non-substitutable product variants as distinct stable item IDs mapped to their parent group. Keep this slice storage/identity/migration only: no new production, market action, observation, model, balance or UI rule is authorized here.

## Ownership and data shape

- Add a stateless `good_catalog.hpp` with strongly typed `GoodGroup`, `GoodId`, catalog metadata, valid-ID checks, and the seven-slot migration table. Use `std::array<int64_t, kGoodIdCount>` for Person, Province, Establishment and Realm conservation totals in this slice; 27 flattened products are bounded and deterministic. Keep zero as a valid GoodId, never a missing-value sentinel.
- Inventory helpers centralize checked reads/writes and prevent indexing with legacy command slots. Current seven-slot actions and the 512-element observation shape remain byte/shape compatible; boundary adapters map their pilot goods to the catalog IDs.
- Expand the Realm bonded-goods vector and Campaign validation to the canonical product count without changing the Campaign payload record order. Keep serialized M4 cargo good IDs 0..6 unchanged and map them to canonical IDs only at Realm pickup/delivery accounting.
- `Establishment.stock` expands from the Gate 1 16 group slots to product IDs. Its save section tag advances from `ESTABLISH_1` to `ESTABLISH_2`; `POLYEC_REALM_12` remains readable and is migrated explicitly to the new Realm schema. Do not infer extra goods or establishments.

## Migration contract

- Old Person/Province/save-ledger slots map exactly: food→DryFood, fiber→Fiber, cloth→Cloth, iron→Iron, fuel→Fuel, tools→Tools, horses→Horse. All other new IDs start at zero.
- Existing opening/produced/consumed totals, bonded Campaign cargo, conservation invariants and Establishment stocks use the same item map. The total of each old slot before and after load must match exactly; no value may be counted in both an old slot and its canonical destination.
- Legacy action command IDs 0..6 keep their old behavior through a named adapter. New catalog IDs are not accepted as old action indices. No recipe or UI can spend newly added goods in this gate.
- Save decoding parses old integer slots, maps into a staged canonical record, validates bounds/nonnegativity/uniqueness, then commits only after all Realm, Campaign and bonded-goods invariants pass. Failed/truncated/malformed loads leave the destination fingerprint unchanged.
- Existing v7–v12 saves load. v12 `ESTABLISH_1` group inventory maps its 16 slots through Gate 1's legacy-good table; current invariants ensure unmapped/variant-ambiguous slots are zero. The seven mapped slots become DryFood, Fuel, Iron, Fiber, Cloth, Horse, and Tools exactly. No silent lossy migration.
- The new Realm schema changes primary conservation-ledger and Person/Province stock widths, so it is `POLYEC_REALM_13`; it writes `ESTABLISH_2` and continues to use `SCHEDULE_5`. Only schema 13 reads 27 product counters; schemas 7–12 retain historical widths/tags.

## Deferred recipe matrix for the next gate

Catalog identity does not authorize production. The next recipe plan must classify all products as raw/extracted, harvested/husbanded or crafted and state exact integer inputs/outputs, variant constraints, capacity/day behavior and resource requirements. Initial working recipe rows from the delegated contract remain: Fiber→Cloth; Iron+Fuel→Tools; Tools+Cloth→MilitarySupply. Documented constraints to encode include Copper, Silver and Gold not substituting for Iron or one another; Horse, WarHorse and Livestock not freely substituting; and Silk not substituting for common Cloth. Other products require explicit production-source rows before they may be generated; no implicit `region % 7`, invented harvest, substitution or free output.

## Self-review and gate decision

This slice preserves old AI dimensions and action meaning, and confines schema changes to explicitly mapped holdings. Key risk was save shape: Person/Province/Campaign records are hand-written formats, so literal migration fixtures were added rather than relying only on round-trip tests from the new writer. The inventory representation is fixed and bounded at 27 products; it does not allocate a dense person-to-person relationship structure. Gate 3 passed Windows Release/Debug core regressions, Python parity, and Godot/benchmark consumer builds. Production remains blocked until a reviewed complete recipe/source and variant matrix exists.
