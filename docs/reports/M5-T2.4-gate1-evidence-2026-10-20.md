## Accepted scope

Gate 1 adds Realm-owned, stable Establishment records; typed owner and industry IDs; an atomic funded create command; cash and stock accounting; and the `POLYEC_REALM_11` / `ESTABLISH_1` save extension. Schemas 7–10 continue to load with an empty Establishment collection. Campaign's 622-byte state payload remains byte-identical.

The accepted source plan is [M5 T2.4 Gate 1 plan](../design/M5-T2.4-gate1-plan.md); delegated working assumptions are in the [Establishment/production contract](../design/M5-T2.4-establishment-production-contract-proposal.md).

## Implementation and review

OpenCode added the Establishment value/codec and the first Realm command/accounting integration. Its later attempts stopped before completing the loader/tests. Following the repository's explicit fallback rule, Codex completed the v11 loader/invariant wiring and Gate 1 tests, then reviewed the complete scoped diff and verified the acceptance gates.

The schedule-section reader's existing upper schema bound was 10, so the reviewed scope was extended to `core/include/polyec/schedule_section_codec.hpp`: it now reads the unchanged `SCHEDULE_4` grammar for Realm schema 11. No schedule section bytes changed. The Campaign payload golden remained 622 bytes.

The final diff validates positive capacity and funding, actor/sequence/counter/ID bounds, owner authorization and source balances before mutation. It keeps Person IDs in their positional namespace, allocates Establishments through `next_id_`, returns the created ID through `RealmResult::session`, and emits fact kind 203. Invariant checks cover all 16 stock slots, legacy stock conservation, unmapped slots, owner references and shared non-Person ID collisions. The establishment codec uses strict sorted-ID validation so duplicate detection is linear rather than quadratic.
