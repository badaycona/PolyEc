## Changes

- New Work commands require a live site ID, region assertion matching that site's region, and an actor physically present there. Generic sessions require site ID zero. Rejected submissions leave the Realm fingerprint and counters unchanged.
- Same-site overlaps remain valid and accrue one interval union. Overlap with another site or an unassigned legacy Work record rejects. Adjacent work at two sites attributes independently.
- Added sparse positive-only `(actor, establishment)` attendance. The Realm invariant checks each reference, per-actor global total and per-region ledger; all attendance changes use the staged ScheduleBook.
- Writer emits `POLYEC_REALM_12` / `SCHEDULE_5`. Readers preserve schemas 7–11; v11 Establishments survive migration while older Work remains unassigned and receives no retroactive site attendance. Campaign's embedded payload is unchanged.
- Python exposes the existing Establishment create command and read-only snapshot, adds a trailing Worksite argument, and reports site IDs/attendance through the same C++ core.
- Frozen `SCHEDULE_5` bytes, legacy migration, malformed site-ledger rejection, worksite retention on reprioritize, cross-site atomic reject, and site/region/global attendance reconciliation are covered.
