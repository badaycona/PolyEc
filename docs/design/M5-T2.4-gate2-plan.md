## Scope

Bind each newly submitted `ActivityKind::Work` session to one Realm-owned Establishment, derive its region from that record, reject overlapping work at different sites, and track cumulative attended ticks by `(actor, establishment)`. Keep the existing per-actor and per-actor/region maps unchanged for T2.2/T2.3 settlement. Do not implement recipe inputs/outputs, payroll source changes, catalog expansion, UI, action/observation/model changes, or organization lifecycle.

## Command contract

- Generic requires `region == -1` and `establishment_id == 0`; existing Generic command calls remain valid.
- Python binding adds `establishment_command(...) -> (success, reason, establishment_id)` and `establishments() -> sorted read-only records`; these only expose the existing C++ Realm command/query and introduce no parallel rules.
- New Work submission requires an existing Establishment ID, `cmd.region == establishment.region`, `actor.region == establishment.region`, and actor alive and not currently travelling (`destination == -1`). Realm stores the region from the Establishment after validating the supplied compatibility assertion.
- A Work submission is rejected if its half-open interval overlaps a non-retired Work session for the same actor whose Establishment ID differs. This includes a legacy unassigned session with ID 0; Realm cannot guess that it belongs to the new site. Overlap at the same site remains valid and counts attendance once through interval union.
- Legacy Work sessions loaded from schemas 7–11 retain `establishment_id == 0`, stored region and existing attendance/pay behavior. They are never assigned to a new Establishment. Site 0 is load compatibility only; new Work commands must name a site.
- Submit validates actor, sequence/counter bounds, site reference, physical region, interval bounds, overlap and attention arithmetic before committing session ID, ScheduleBook, actor counters or fact. Cancel/Reprioritize preserve the site's ID; no operation can retarget a session. Establishments are persistent in this gate and have no delete/move operation.

## Attendance and invariants

- For each actor and site, intersect non-retired site Work sessions with the current advance chunk, then credit the interval union only if the actor is alive, not travelling and physically in the Establishment's region. Overlap at one site counts once. Cross-site overlap is prevented at submit.
- `work_present_ticks_by_establishment` is sparse, positive-only, monotonic and keyed by `(actor, establishment_id)`. Each key must reference an existing actor and Establishment; ticks are no greater than the ScheduleBook cursor. Per-actor sums across sites cannot exceed global attendance. Legacy ID-0 Work does not populate this map. Existing region attendance/pay maps keep their prior behavior.
- Checked additions and staged ScheduleBook updates preserve advance atomicity. The final load invariant cross-checks each site reference and its region against the Establishment table; no Person ID namespace is mixed into site IDs.

## Save migration

- Writer emits `POLYEC_REALM_12` and `SCHEDULE_5`.
- Realm schema 12 uses `SCHEDULE_5`; schemas 10–11 continue to use `SCHEDULE_4`; schemas 7, 8 and 9 retain their existing tags/layouts. Existing `ESTABLISH_1` parsing remains after the schedule section for schema 11 and 12.
- `SCHEDULE_5` includes all `SCHEDULE_4` fields in their existing order, appends `establishment_id` to serialized session records, and appends the sorted sparse site-attendance map. Its reader validates counts, integer ranges, duplicates, cursor bounds and local consistency before publishing.
- Loading v7–v11 sets session site IDs to zero and the site-attendance map empty. V7–v10 still load with no Establishments; v11 retains its explicitly saved Establishments but old Work remains unassigned. No historical work or attendance is retroactively credited to a site.
- Campaign's state payload and quoted Realm boundary stay structurally unchanged; only its current Realm magic assertion changes to v12.
