# T4.5 — schema scenario chọn được cho năng lực đã đăng ký

Ngày: 2026-10-22  
Nhóm: M5.0/1 — capability schema gắn với từng cá thể  
Trạng thái: kế hoạch trước khi sửa source

## Mục tiêu và phạm vi của lát

Thay vì coi sáu số trong `Stats` luôn luôn là sáu chiều bắt buộc, Realm sẽ giữ một schema hoạt động được chọn từ các capability đã đăng ký. Scenario/experiment có thể chọn một tập không rỗng trong sáu ID kế thừa; mặc định vẫn chọn đủ sáu để giữ hành vi hiện hành. Mỗi Person tiếp tục sở hữu các giá trị nguyên theo đúng sáu ID ổn định; schema Realm xác định dimension nào thuộc vector chức năng của mọi cá thể trong scenario.

Lát này không đăng ký `technical`, `labor` hay dimension mới. Mỗi capability được chấp nhận phải có luật core hiện hành, observation slot và phép kiểm. Một ID mới chỉ được thêm cùng effect có căn cứ, chuẩn hóa, migration/model contract và test tương ứng; schema lạ hoặc mask có bit chưa đăng ký phải bị từ chối.

## Định danh, đơn vị và hiệu ứng

ID dùng đúng khóa ổn định đã thêm ở T4.4: `strategy`, `administration`, `economic_planning`, `diplomacy`, `investigation`, `military`; thứ tự/bit trong mask lần lượt là 0–5. Mỗi giá trị là số nguyên trên miền hợp lệ **0–100**. Đơn vị gọi là `legacy capability point` (điểm năng lực kế thừa); đây là working scale để tương thích dữ liệu hiện hành, chưa được hiệu chuẩn như năng suất hoặc xác suất thực tế.

| ID | Luật core sử dụng giá trị khi dimension đang hoạt động |
|---|---|
| `strategy` | Khi học hoàn tất, cộng `5 + value/20` điểm kỹ năng ngoài phần giáo viên. |
| `administration` | Tính độ trễ một số báo cáo và năng suất/thời hạn dự án. |
| `economic_planning` | Giảm thời gian chuẩn bị dự án; không giảm bill hoặc vật tư. |
| `diplomacy` | Tính thời gian chuẩn bị đề nghị ngoại giao/hôn nhân. |
| `investigation` | Tính hạn Investigation. |
| `military` | Tính mức giảm bất ổn khi huy động. |

Khi scenario bỏ một ID, consumer của ID đó dùng giá trị trung tính phiên bản `capability-schema-v1 = 50`. Giá trị 50 là trung điểm của miền, đồng thời là working assumption cho các công thức cũ; nó không khẳng định cân bằng được chứng minh. Giá trị thô của Person vẫn được giữ để có thể khôi phục schema đầy đủ khi save/load hoặc khi chuyển về scenario tương thích.

## Scenario, observation và model

- C++ constructor và `Realm::scenario` nhận mask schema; Python Realm constructor/scenario cũng nhận mask tùy chọn. Mặc định là mask đủ sáu ID. Mask `0`, bit ngoài sáu bit đăng ký hoặc kiểu dữ liệu ngoài miền bị reject trước khi khởi tạo.
- Observation giữ tensor 1.676 chiều, 128 state slot, 129 action và vị trí legacy 10–15. Slot của dimension đang hoạt động nhận `value/100`; slot bị bỏ nhận `50/100`. Như vậy model hiện hành không đổi khi dùng schema mặc định.
- Model contract mặc định giữ chuỗi hiện tại. Với schema con, chuỗi thêm mask schema theo dạng cố định; manifest không khớp bị runtime từ chối trước inference. Override dev không được biến model của schema khác thành model tương thích sản phẩm.
- Schema được lưu bằng section cuối `CAPABILITY_SCHEMA_1 <mask>` trong Realm save32. Reader schema7–31 mặc định schema đủ sáu và ánh xạ nguyên trạng sáu giá trị Person theo mapping T4.1; save cũ không bị diễn giải lại theo schema thiếu. Reader schema32 reject section thiếu, mask rỗng, bit chưa đăng ký hoặc token thừa. Load vẫn stage toàn Realm rồi chỉ publish nếu invariant đạt.
- T4.5 không đổi action, reward, chọn policy, tiền, quyền, knowledge, UI visibility hoặc cách sinh sáu giá trị. Người chơi vốn đã thấy sáu số. Python/native/runtime phải nhận model contract mới qua đúng C++ `Realm`; chưa train/evaluate trong lát này.

## Source dự kiến

- `core/include/polyec/realm.hpp`: định nghĩa thứ tự ID/mask, neutral value, mask getter, accessor kiểm tra capability đang hoạt động; thay các luật đọc trực tiếp `Stats` bằng accessor Realm.
- `core/src/realm.cpp`, `core/src/realm_court.cpp`, `core/src/realm_lifecycle.cpp`: dùng accessor mới; observation giữ slot cũ và điền trung tính cho ID bị bỏ.
- `core/src/realm_save.cpp`: writer Realm32, reader migration 7–31→schema mặc định và section mới.
- `core/include/polyec/schedule_section_codec.hpp`: nhận schema Realm32 trong khi giữ `SCHEDULE_6`.
- `bindings/python/realm_binding.cpp`, `gdext/polyec_session.cpp`, `native/realm_runtime.cpp`: đưa `model_contract` dạng chuỗi động qua binding/runtime và từ chối manifest sai; Python expose mask cho experiment, snapshot giữ `stats`/`legacy_capabilities` tương thích.
- Core tests: mask mặc định; schema con success; dimension bỏ dùng neutral trong luật/observation; mask rỗng/bit lạ/tamper save reject atomic; save/load schema32 giữ mask và giá trị; schema31 migrate sang đủ sáu; contract khác nhau giữa default/schema con.
- Test fixture tạo save31/hash phải bỏ section mới chính xác, không viết lại oracle/hash cũ.

## Build và kiểm ngay

Ngay sau source, build Release `polyec_realm_tests`, `polyec_court_tests`, `polyec_schedule_tests` (các test này kiểm save/schema, court và schedule) và Python binding `polyec_env`. Chạy trực tiếp ba executable C++ và test binding nhỏ qua C++ core. Build GDExtension target `polyec` sau khi kiểu trả `model_contract` đổi; chạy Godot model-guard smoke chỉ nếu có manifest fixture không cần ONNX. Không build toàn bộ app, full CTest, Debug hoặc chạy replay Python toàn pipeline chỉ vì đổi codec. Lưu đúng output/failed attempt vào report.

## Ranh giới đóng nhóm và phần còn thiếu

Đóng T4.5 khi người gọi C++/Python chọn được schema con hợp lệ, luật và observation dùng trung tính đã ghi rõ, schema32 roundtrip/reject/migrate schema7–31 trong C++, default model giữ tương thích, runtime từ chối schema contract không khớp, và các test bị ảnh hưởng pass. Python binding phải xác nhận API nhận mask và cùng observation/model contract với C++.

Đây mới là schema cấu hình tập con của sáu ID đã được triển khai. Nó chưa cung cấp capability kỹ thuật/lao động mới, dimension riêng từng cá thể, personality/trait, tăng trưởng năng lực, quyền quan sát cho NPC khác, Godot chọn scenario schema, RL đã học dùng năng lực, hoặc đánh giá R3. Các phần đó tiếp tục là M5 backlog; không ghi T4.5 là hoàn tất capability đầy đủ.
